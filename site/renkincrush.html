RENKINcrush

連鎖パズル × 5種のミニゲーム

9ターンで高得点を狙う、連鎖パズルと5種類のミニゲームを組み合わせたゲームです。ブロックの選択から落下・連鎖を考え、4連鎖以上で発生するミニゲームの追加消去を狙います。

主な貢献：ASOBEから連鎖中心の仕様への再設計を提案。さらに外部試遊で指摘された移行時の中断感に対して、ChainCheckを提案・実装しました。現行Swapの企画・実装、Timingの初期実装、ハイライト表示なども担当しました。

作品概要

15列×13行・5色の盤面から同色グループを選んで直接消去します。落下後、着地したブロックを起点に同色3個以上のつながりがあれば自動消去を繰り返し、連鎖が成立します。連鎖が終わったあと、補充と結果表示を経て4連鎖以上ならミニゲームへ。発生する種類は最初に選んだ色で決まり、成功するとゲームごとに異なる範囲を追加消去します。9ターンのスコア・称号・ランキングを競います。

02

制作背景・挑戦したこと・学んだこと

制作背景

「積みゲーを解消する」を遊びにする

最初は「積みゲーを解消する」という発想でした。試作版ASOBE（Ver0517）では、積まれた盤面から同色の塊を選び、対応するミニゲームを成功させてブロックを消す全消し型パズルを試作しました。

問題の発見と再設計

原案の魅力を残し、遊びの中心を再設計

試遊でルールの分かりにくさを指摘され、ブロック消去のたびに別の操作・判断を求める構造を課題と捉えました。盤面の連鎖とスコアを主役にし、ミニゲームを4連鎖以上の報酬へ変更する仕様を提案しました。この変更は外部試遊会での後続改善とは別の段階です。

学んだこと

案の数だけでなく、理由を言語化して共有する

大きな仕様変更には反対意見もあったため、新旧仕様の違い、実装可能性、教員・クラスメートの試遊評価を判断材料として共有しました。結果だけでなく、変更の理由と検証の過程を説明する重要性を学びました。

PLAY EXPERIENCE REDESIGN

旧版「ASOBE」からRENKINcrushへ

初期の「積みゲーを解消する」案から、旧版ASOBE（Gitブランチ Ver0517）を経て、連鎖とスコア中心のゲームへ再設計しました。以下は旧版の実プレイ画面と、再設計後の記録画面です。

BEFORE / ASOBE・Ver0517

ミニゲームの成功がブロック消去の条件

  1. あらかじめ積まれた盤面から同色の塊を選ぶ
  2. 選んだ色に対応するミニゲームを遊ぶ
  3. 成功した場合、同色でつながる塊を消去
  4. 全消しを目指す

課題と捉えた点：パズルで消す場所を考えても、消去には毎回別の操作・判断が必要であり、思考の流れが途切れやすいと判断しました。

AFTER / RENKINcrush

連鎖の成果をミニゲームに結び付ける

  1. 同色グループを選択し、そのまま消去する
  2. 落下後、着地を起点に同色3個以上なら自動連鎖
  3. 連鎖終了後に結果を案内・盤面を補充
  4. 4連鎖以上なら最初に選んだ色のミニゲームが発生
  5. 追加消去を使い、9ターンでスコアを競う

狙った体験：盤面の選択と連鎖を遊びの中心に置き、ミニゲームを大連鎖の報酬としました。

初期の再設計：「ミニゲーム成功がブロック消去の条件」から、「連鎖達成後にボーナスとしてミニゲームを遊ぶ」構造へ。旧版にも盤面判断はあり、その役割を組み直した点が変更の中心です。

※旧版は開発途中の Ver0517 で、最初期の原案とは異なります。比較画像の「再設計後」は保存時点の画面であり、10月29日時点のUIを再現するものではありません。統一した指標による新旧比較データは未整理です。

仕様変更時の合意形成

原案を維持したい意見に対し、旧仕様の問題点だけでなく、変更後のゲームフロー、実現したい体験、 残り期間で実装できる案を示しました。各メンバーの案や軽い試作を確認した後、先生方にもレビューを依頼し、 チームで最終仕様を決定しました。自分の案を押し通すのではなく、判断材料を増やして共通認識を作ることを意識しました。

PROBLEM SOLVING

発見・改善した主な問題

企画、操作設計、プログラムの異なる観点から、問題の原因を整理して対応しました。

企画・ゲームフロー

パズルとミニゲームによって遊びが途切れる

問題
消去のたびにミニゲームを開始するため、パズルで場所を考えた直後に操作と判断の対象が切り替わる構造でした。
原因
盤面管理とミニゲームはルール上で連動していましたが、消去の必須条件としてミニゲームを置いたため、パズルの流れを中断しやすいと考えました。
対応
連鎖を中心体験に定め、ブロックを直接消去できるよう変更。ミニゲームは4連鎖以上の報酬として発生させました。
結果
全消し型から9ターン制スコアアタックへ再設計し、ゲームを完成させました。旧版との共通条件での定量比較は未整理です。

操作・ルール理解

ミニゲームごとのルールと操作が分かりにくい

問題
パズル本編とミニゲームで使用する操作が統一されておらず、ルールも初見では理解しにくい状態でした。
原因
パズルは十字キーとAボタンで完結する一方、ミニゲーム側では操作方法と成功条件が個別に設計されていました。
対応
方向入力・決定を基本とした操作設計に加え、ミニゲーム開始前に個別の操作や目的を提示する準備時間を設けました。
結果
操作・成功条件を開始前に確認できる構造にしました。ただし、ミニゲーム間の操作差や難易度には改善余地があります。

プログラム・スコア処理

追加消去時に異常な量のスコアが加算される

問題
ShootingとButtonBashのクリア後、一部の追加消去で想定を超えるスコアが加算されていました。
原因
ブロックが存在しない色Noneの空マスにもErasing状態を設定し、Erasing状態のセル数をそのまま消去数として数えていました。
対応
セルの色がNoneの場合は、消去数とスコア加算の対象に含めない条件を追加しました。
結果
実際にブロックが存在するセルだけが消去数として集計され、意図したスコアが加算されるようになりました。

FIELD REVIEW

外部試遊の指摘を次の改善へつなげる

初期の仕様再設計後、試遊会で連鎖の爽快感とともに、ミニゲームへの移行による中断感が指摘されました。これを受けて本人がChainCheckを提案・実装しました。一方、改善後の再試遊データと、連鎖の主体性を高める仕組みには課題が残っています。

学生の試遊コメント

消去の爽快感を評価

ブロックの消去演出や連鎖の楽しさに好意的な反応がありました。一方、ミニゲームの難易度や、既に3個以上つながったブロックの扱いも指摘されました。

イリンクスからの試遊コメント

ミニゲームへの移行が早い

ミニゲームの発想と出来を評価する一方、連鎖の爽快感が続く途中で遊びが切り替わる点を指摘されました。

サイバーコネクトツーからの試遊コメント

大連鎖の動機はあるが、主体性が弱い

ルールの分かりやすさと4連鎖のボーナスを評価する一方、起点選択以外に介入できる操作が少なく、連鎖を運任せに感じやすいという指摘を受けました。

指摘後の対応と現在地

論点反映・確認できたこと現時点の評価
ミニゲームが連鎖の爽快感を中断する本人がChainCheckを提案・実装。 連鎖が完全に終わったあと連鎖数と次の展開を表示し、補充・案内を経てミニゲームへ移行するよう整理。実装を現行ソースで確認。中断感が減ったかは再試遊で未検証。
連鎖を自分で組み立てる余地が少ない選択グループのハイライトはあるが、入力操作は基本的に消去起点の選択。連鎖は落下と補充結果に左右される。継続課題。解決したとは記載しない。
既に3個以上つながったブロックが消えない現行コードは着地したブロックを起点に自動連鎖を判定するため、既存の塊すべてが自動消去される仕様ではない。仕様の説明・理解促進を含め検討が必要。

本人による提案・実装：ChainCheck

「4連鎖達成の嬉しさが中断される」という指摘に対し、連鎖完了とミニゲーム開始の間に、結果を見せる専用の繋ぎを設計しました。

  1. 連鎖が終了
  2. 連鎖数と次の展開を案内
  3. 裏で盤面補充、移行条件を確認
  4. ミニゲームへ移行

企画と実装は本人が担当。狙いは連鎖の成果を一度受け止め、別の遊びへ移ることを理解しやすくすること。改善後の満足度・中断感は定量検証していません。

資料：『【2026】試遊会_コメント一覧』と2026年10月29日時点のソース読解資料。Cygamesから別途受けた作品講評とは異なる機会です。個別の評価は作品全体の合格・推薦を意味しません。変更の厳密な実施日と改善後の反応は追加確認が必要です。

03

こだわった（工夫した）こと

作品の核となる体験と、そこへつなげるための設計・実装を4項目に整理しました。

01 / GAME DESIGN

消去条件ではなく、連鎖の達成報酬へ

再設計後は、パズルの流れを保ちながら、大連鎖の成果をミニゲームにつなぐようにしました。

Ver0517では毎回ミニゲームをクリアしなければブロックを消せませんでした。新仕様では直接消去と落下連鎖を中心にし、4連鎖以上の達成時にボーナスとして発生させます。試遊会後は本人がChainCheckを提案・実装し、連鎖終了後の結果案内・補充を挟むよう変更しました。

02 / BALANCE DESIGN

「4連鎖」を報酬条件に設定

狙った連鎖と偶然の連鎖がどちらも起きるよう、プレイ確認を踏まえて発生条件を決めました。

4連鎖以上をミニゲーム条件として採用しました。ただし、連鎖発生率の再現可能な計測は未整理です。外部試遊では「運任せに感じられる」という指摘もあり、プレイヤー自身の判断で連鎖を作れる余地は今後の検討課題です。

03 / IMPLEMENTATION

現行Swapの提案・実装とTimingの初期実装

現行のSwapは企画と実装を本人が担当しました。Timingの初期実装も担当しています。

現行Swapは、錬金液と泡を注いで目標比率を目指すゲームとして本人が提案・実装しました。また、Timingは3本のバーを順番に止める初期版の処理を担当しました（画像素材を除く）。Timingの後続改修における個別の担当範囲は確認中です。

04 / USABILITY

選択範囲を事前に伝えるハイライト

決定後の結果を予測しやすくし、連鎖を考えるための情報を画面上に追加しました。

上下左右につながる同色グループを選択前に強調し、消去範囲を分かりやすくしました。落下後の展開を読みやすくするための情報提示ですが、実際に連鎖をどこまで操作できるかは別の問題で、試遊で指摘された主体性の課題は引き続き残っています。

GAME SPECIFICATION

ゲーム仕様

現在の実装を、採用担当が短時間で把握できる情報に絞っています。

15 × 13盤面サイズ
5色ブロックとミニゲームの種類

4連鎖にした理由

実際のプレイで連鎖が偶然にも意図的にも発生することを観察し、報酬条件として採用しました。ただし、外部試遊で操作の主体性が弱いとの指摘を受けており、再現性のある発生率・改善効果のデータは未整理です。

9ターンにした理由

5種類のミニゲームを複数体験できる可能性を残しながら、1プレイが長くなりすぎて飽きない範囲として設定しました。

5種類にした理由

種類が少なすぎる単調さと、色が多すぎる視認性低下の間を取り、5色のブロックと5種類のミニゲームを対応させました。

1ターンの流れ

  1. 1起点を選ぶ同色の連結ブロックを選択して直接消去
  2. 2落下と連鎖着地を起点に同色3個以上で自動消去
  3. 3連鎖終了連鎖結果を表示、盤面を補充
  4. 44連鎖でボーナス最初に選択した色のミニゲームを開始（最大1回）
  5. 5成功時は追加消去ミニゲームごとの特殊範囲を消し、連鎖を再処理
  6. 69ターンで終了スコア・称号・ランキングを表示

5種類のミニゲーム

RED

Shooting

30秒以内に敵を倒すシューティング。成功時には敵位置を中心とした爆発範囲のブロックを追加消去します。

BLUE

Action

床を上げるアクションを3回成功させるゲーム。成功時には盤面の下側6行を追加消去します。

YELLOW

Swap 企画・実装担当

15秒以内に錬金液と泡を注ぎ、指定された液体比率（目標±10ポイント）へ調合。成功時は盤面中央から半径270px以内を追加消去。

BROWN

ButtonBash

5秒以内に23回のボタン入力を成功させ、中央を中心に半径250px程度の範囲を追加消去します。

GREEN

Timing 初期実装担当

3本のバーを順番に止め、最初の停止位置を基準に残り2本を±45px以内へ。成功時は対応する行と上下2行を追加消去。

企画・実装上の役割：現行Swap（調合ゲーム）の提案と実装、Timingの初期実装、ハイライト表示の実装は本人が担当しました。ButtonBashの初期内容も提案し、Action・Shootingはチームで検討しました。Timingの後続改修およびAI補助の範囲は提出前に確認します。

  • 2026年4月11日に制作開始。ASOBE型から連鎖中心のスコアアタックへ再設計し、東京ゲームショウ2026へ出展しました。
  • 6月26日以降も調整を継続。外部試遊で指摘された中断感に対し、本人がChainCheckを提案・実装し、連鎖終了後の結果表示と補充を経てミニゲームへ移行する流れを設けました。
  • 外部試遊では、連鎖の爽快感と4連鎖ボーナスの動機付けが肯定的に評価されました。

残った課題

  • 選択起点以外の盤面操作が少なく、連鎖を運任せに感じられるという指摘への対応は継続課題です。
  • 既に3個以上つながっているグループは、着地起点がないと自動消去されないため、ルール理解に課題があります。
  • 変更後の試遊結果、旧版との定量比較、4連鎖の発生率の再現可能な検証は未整理です。

外部試遊会（学生・イリンクス・サイバーコネクトツー）のコメントは本ページの「外部試遊」欄に整理しています。別途、Cygamesの関係者にも作品を見せて講評を受けていますが、高い評価を受けたという主張はしていません。

今後は、ミニゲーム移行時の中断感と、自分の判断で大連鎖を作れる感覚について共通の試遊項目を用意し、旧版や改善前の体験と比較できる形で評価したいと考えています。
